assumptions:
  - "Architecture inferred from Travis CI patterns: edge router + web app + Rails API + PostgreSQL + Redis queue + scheduler + worker fleet + GitHub syncer; exact internal service boundaries were adapted for a compact causal graph."
  - "To make request paths mechanically checkable while still emitting database logs mid-flow, some bidirectional/return-path network hops are modeled as 'logical response' edges (e.g., postgres_primary -> api_service, api_service -> web_app). This reflects response traffic on established connections rather than true request initiation by the downstream component."
  - "TRUNCATE semantics were modeled as 'tables emptied but relations remain': most reads succeed and return zero rows (postgres_primary.sql_exec with low/zero rows), while some writes fail via realistic constraint violations (postgres_primary.sql_error with SQLSTATE 23503/23505)."
  - "The postgres_primary.sql_exec template models state-dependent variability in result size by defining the {rows} domain only under state_vars (normal: broader; failure: near-zero), while other SQL fields keep a single shared domain."
  - "Cron activity during the empty-data window is modeled as a successful scan with zero candidates (build_scheduler.cron_scan_complete), not as a query error; the scheduler 'not running' problem is modeled later as a separate steady-state symptom."
  - "GitHub sync during the empty-data window is modeled as succeeding while recreating users: github_syncer.upsert_missing_user provides an explicit signal that upserts occurred due to missing rows; this is distinct from sync_error, which is reserved for true failures."
  - "Timeline compressed to fit a 50-minute, two-phase scenario while preserving ordering: truncate executes -> apps briefly run against empty data -> apps taken offline -> restore -> service returns with token/user mismatch + backlog + scheduler not restarted."
  - "Blank profiles modeled as web_app.render_blank_profile driven by api_service.profile_not_found and postgres_primary.sql_exec returning low/zero rows during the empty-data window."
  - "Sequence behavior modeled via api_service.user_created_after_truncate including seq_last_value; PostgreSQL 'TRUNCATE does not reset sequences' is treated as external knowledge, not directly proven by logs alone."
  - "Cron scheduler missed restart modeled as build_scheduler.scheduler_not_running plus api_service.scheduled_job_missed after restore; scheduler heartbeats are suppressed during the interval where the scheduler is not actually running."
  - "JWT-subject variable naming was aligned across api_service.authn_from_jwt and api_service.jwt_user_mismatch (sub_user_id) so a single request can produce causally consistent log chains for a given token_id."
  - "Estimated normal logs/min: background ~23.3/min plus flows ~1467/min => ~1490.3/min; over 25 min => ~37,258 lines."
