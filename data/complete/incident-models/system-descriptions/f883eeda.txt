assumptions:
  - |-
    Added logical return-hop edges (mysql_rds->quay_app and quay_app->ingress_router) to satisfy path connectivity checks; these represent responses/results, not new primary dependencies.
  - |-
    Traffic volumes are intentionally scaled down (hundreds of rpm) while preserving the incident’s causal relationships (App Registry surge dominates and drives DB contention).
  - |-
    MySQL connection counts are scaled down to match the modeled request throughput/latencies; “connection storm” is represented as a sharp relative jump toward configured max_connections plus frequent connection refusals and lock waits.
  - |-
    Split Quay request error logging into pre-query failures (quay_app.req_error: connect refused/pool exhausted/read-only) vs post-query failures (quay_app.req_error_db: lock wait/timeouts) to avoid contradictory per-request log sequences.
  - |-
    Quay's DB-connection limiting mitigation is modeled as an explicit config marker (quay_app.mode_changed with db_conn_limit); per-request db_acquire does not include a limit field to avoid implying the limit existed before the mitigation event.
  - |-
    MySQL threads_running domains are constrained to not exceed the corresponding connection maxima for each conn_stats_* template; generators should choose coherent samples where threads_running <= current_conns.
  - |-
    Fixed max_conns within each MySQL conn_stats_* log type to prevent unrealistic combinations where current_conns > max_conns during generation (storm uses max=260; capped uses max=110).
  - |-
    App Registry slowness is modeled as high DB query latency and larger row counts, which increases connection hold time and contention symptoms (lock_wait, too_many_conn, 502s).
  - |-
    Read-only stabilization and feature reduction are represented by a config marker (mode_changed), shifting push failures to 503, and disabling gc_run via event multipliers.
  - |-
    Estimated baseline normal logs/min ≈ 600 (flows) + ~13 (background); estimated total logs for the scenario ≈ 56k (target 20k..100k).
