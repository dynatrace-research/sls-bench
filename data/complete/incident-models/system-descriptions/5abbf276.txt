assumptions:
  - |
    The global network is modeled as three representative edge hosts plus a single control-plane KV node.
  - |
    The incident is modeled through the global WAF termination and its post-mitigation degraded steady state;
    later full WAF re-enable is out of scope so the scenario ends with WAF disabled.
  - |
    WAF "simulate mode" still executes the regex and can consume CPU; this is represented by high waf_ms values
    in http_worker.req_done (for the fraction that complete) and sampled waf_engine.regex_backtrack_warn logs.
  - |
    Paging semantics are thresholded/aggregated: synth_monitor.page_sent is emitted only as scenario one-shots,
    not once per failed synthetic request.
  - |
    To avoid contradicting normal fast access log domains, degraded-but-successful requests use edge_frontend.access_ok_slow
    while normal and post-terminate successes use edge_frontend.access_ok.
  - |
    Normal-phase estimate: ~300 rpm user traffic * 3 logs/request ≈ 900 logs/min, plus ~12 logs/min metrics/synth noise.
  - |
    Total estimate over the 60-minute scenario: ~43k-48k logs (within 20k..100k), dominated by per-request edge/worker logs.
  - |
    Key diagnostic visibility comes from: Quicksilver publish markers (one-shots), CPU/5xx metric samples (per-minute),
    frontend upstream timeouts + 502 access logs (high-rate), slow-regex warnings (per-minute until termination), and
    global terminate markers (one-shots).
