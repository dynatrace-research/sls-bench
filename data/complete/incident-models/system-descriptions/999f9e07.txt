assumptions:
  - |
    Host counts are reduced to a minimal incident-sufficient fleet: 3 ZooKeeper nodes, 2 observer nodes, 3 proxies, 2 control-plane API hosts, and 4 Kibana/TLS-sidecar hosts.
  - |
    Elasticsearch nodes themselves are not modeled; proxy access logs represent the outcome of routing attempts for Elasticsearch and Kibana traffic.
  - |
    Proxy and console access logs are modeled as per-attempt logs when retries are enabled (i.e., multiple attempt logs can exist for one higher-level client operation); retry marker logs are emitted only on attempts 2..N.
  - |
    The runc/kernel softlock issue is modeled as discrete CRITICAL one-shots on ZooKeeper hosts, representing operator debugging interactions that can render hosts unresponsive.
  - |
    Late-stage Kibana conntrack/socket exhaustion is modeled with distinct background metric logs (kibana_instance.open_sockets_pressure, tls_proxy.conntrack_pressure) that are suppressed early in failure and enabled only in the late failure event; baseline socket/conntrack metrics remain moderate through most of failure.
  - |
    Kibana proxy-access errors are split into two templates: proxy_kb_access_err_route (request fails before reaching Kibana due to routing/observer instability) and proxy_kb_access_err_upstream (request reached Kibana and failed/timed out upstream), to keep error semantics consistent with the emitted chain.
  - |
    Success-log attempt fields are constrained to attempt=1 for flows configured with max_attempts=1, avoiding contradictory attempt values.
  - |
    Flow paths include return hops only where needed to preserve chronological ordering for completion-bearing logs (e.g., Kibana logs before proxy access logs for Kibana UI); a Kibana->proxy_router edge models the response direction for those return hops.
  - |
    Two ALB metric templates are used in failure: lb_metrics (degraded) and lb_metrics_recovered (near-baseline). Scenario events swap which one is emitted so the post-stabilization drop can be reflected without widening the degraded value ranges.
  - |
    lb_edge.lb_metrics.req_rps is modeled to align with the modeled external request rates (sum of external flow RPM / 60) with headroom; event-time multipliers model the observed reconnection surge by temporarily increasing successful Elasticsearch request volume after proxy scaling.
  - |
    Quorum-loss semantics are enforced by constraining zk_ensemble.zk_quorum_lost.connected_peers to be strictly less than needed (needed is fixed at 2 for a 3-node ensemble).
  - |
    To avoid self-contradictory high-pressure evidence, kibana_instance open-socket logs model fd_limit as a fixed high value (65535), ensuring open <= fd_limit for all emitted combinations.
  - |
    Volume estimate: normal phase ~17.5k logs (25m) and failure phase ~34k logs (30m), totaling ~52k logs (within the 20k–100k target).
  - |
    Diagnostic visibility is ensured via: lb_edge.lb_metrics / lb_metrics_recovered (global), zk_ensemble.zk_quorum_lost + zk_client_conn_fail (coordination failure),
    proxy_router.proxy_es_access_err + route_lookup_retry (routing failure with retries), zk_observer.observer_sync_timeout + initlimit_changed (observer instability and mitigation),
    and late-only kibana_instance.open_sockets_pressure + tls_proxy.conntrack_pressure (extended Kibana degradation evidence).
