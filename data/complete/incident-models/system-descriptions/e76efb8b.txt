  desc: >
    An account service provides authentication and account-related APIs to game clients.
    All traffic is routed through an Nginx proxy that shortcuts access-token verification via Memcached,
    while other API calls are passed through to a Java (JAXRS) application.
    When the cache tier becomes unstable, Nginx workers block on Memcached timeouts and can become saturated,
    preventing other traffic (including health checks) from reaching the application and causing the load balancer to drain targets.

assumptions:
  - |
    The post-mortem describes multiple unrelated incidents; this model focuses only on the Account Service outage where
    Memcached instability saturated Nginx and caused the ALB to pull all nodes out of rotation.
  - |
    Real-world throughput is orders of magnitude higher; request rates are scaled down to keep a single generated log file
    within 20k..100k entries while preserving relative behavior shifts (cache-hit vs fall-through vs rejection vs ALB 503).
  - |
    To keep saturation signals quantitatively plausible under the scaled request rates, Nginx "workers" and related gauges
    are modeled as a small effective worker pool (single-digit free/busy) rather than hundreds of threads/connections.
  - |
    Memcached/Redis metric-like fields (e.g., ops_s, timeouts_s, active_conns) are scaled down to be qualitatively consistent
    with the scaled-down request rates rather than representing full production traffic.
  - |
    ALB access logs include final status and duration, so flows model them as occurring after upstream processing by adding a
    logical response hop back to alb_gateway at the end of relevant request paths.
  - |
    Token verification is modeled as mostly cache-hit in normal, and mostly Memcached-timeout plus fall-through in failure,
    matching the described 100ms timeout and increased Redis load.
  - |
    Health-check failures are represented as ALB failure-state background warnings (suppressed early, enabled later by scenario events),
    plus a one-shot marker when the target group is drained.
  - |
    Volume estimate for a 50-minute scenario: normal phase about ~1.5k logs/min and failure phase varying by stage, totaling about ~70k logs.
