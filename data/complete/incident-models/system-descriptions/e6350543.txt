sys:
  id: maps_tile_delivery_kartotherian
  desc: >
    A CDN edge (ATS) serves map tile requests for maps.wikimedia.org and forwards a subset of traffic to Kartotherian origins
    through an L4 LVS service. During a capacity shift, some origins run on Kubernetes workers while the rest remain on
    bare metal. Because LVS only balances TCP, TLS is end-to-end between ATS and the origin, so origin certificate/SNI
    compatibility directly affects user-visible success on origin-forwarded requests.

states: {n: normal, f: failure}

components:
  - id: edge_ats
    name: ATS Edge Cache
    svc: ats
    hosts: [ats-edge1, ats-edge2]
    desc: >
      Terminates client connections and proxies origin-forwarded requests to Kartotherian via LVS.
      Uses the requested Host as TLS SNI when connecting to the origin.
    to:
      - dst: lvs_kart
        proto: tcp
        desc: L4-balanced TCP connection to Kartotherian origins (TLS passes through LVS).
      - dst: logstash
        proto: kafka
        desc: Ships structured webrequest logs to centralized logging.
    logs:

assumptions:
  - 'The real incident lasted several hours; it is time-compressed into a 50-minute scenario while preserving ordering (pool -> low-volume 5xx -> dashboard detection -> depool -> root-cause verification pending fix).'
  - 'This model focuses on ATS origin-forwarded traffic; ATS caching/client-hit behavior is not modeled as separate flows to keep the incident mechanism minimal and consistent.'
  - 'LVS is modeled as pure L4 TCP balancing (no TLS termination), matching the causal mechanism that TCP health can succeed while TLS verification fails at ATS.'
  - 'Per-request logging is modeled primarily at ATS (webrequest logs), since that is what feeds the Webrequest 50X dashboard and is the key observable signal.'
  - 'Pooling/depooling and SAL actions are represented as discrete one-shots with fixed action fields to support timeline reconstruction.'
  - 'Dashboard and ATS origin-summary metrics are modeled as two variants (ok vs elevated) so event-time switches can be represented via background-log rate multipliers.'
  - 'Estimated log volume over 50 minutes is ~40k ATS webrequest logs plus a few hundred background/one-shot logs, within the 20k–100k target.'
