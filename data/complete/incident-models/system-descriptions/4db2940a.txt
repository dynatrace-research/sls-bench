  - Component set is minimized to the user-visible surface (edge/app/git), storage HA pair, and network fabric (access/aggregation switches + monitoring).
  - The modeled root cause is an aggregation-switch MAC learning impairment that increases unknown-destination flooding, saturating access↔aggregation links and raising latency/errors.
  - A separate misconfiguration (unsupported link watchdog) can err-disable redundant uplinks during troubleshooting, producing a brief period of complete unavailability.
  - Operator action markers were split into distinct log IDs (connect_uplink/shutdown_uplink/remove_watchdog_setting/enable_uplink) so one-shot emissions cannot contradict event narratives.
  - Normal traffic is approximated at ~400 rpm web and ~60 rpm Git; failure traffic mixes slow successes and timeouts, with a distinct hard-down variant during the outage.
  - Failure-state Git clone/fetch paths include the fileserver hop (even when fileserver does not emit a per-request log) to keep the coarse request route consistent with the modeled storage dependency and with normal operation.
  - Fileserver HA degradation is modeled as a rare Git 500 error path (~1.5 rpm) plus HA peer-disconnect background logs to keep the side effect visible without inflating user impact.
  - Estimated log volume for a 55-minute scenario is ~44k (mostly per-request access/app/git logs, plus hundreds of network telemetry logs), within the 20k..100k target.
