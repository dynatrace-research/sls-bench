assumptions:
  - |
    The post-mortem describes many Microsoft 365 services; this model collapses them into one edge gateway and one backend cluster
    to preserve the WAN/DNS failure mechanism.
  - |
    DNS answers/timeouts return to the edge gateway (modeled as dns_resolver -> m365_edge_gateway) to keep request paths traversable.
  - |
    Gateway "retries" are modeled as explicit upstream_retry/upstream_timeout log steps within a single request lifecycle, so the terminal
    client response log (resp_504_*) is emitted exactly once per failed request (no retry block on those flows).
  - |
    WAN impact "in waves" is represented via time-windowed multiplier changes (one prominent spike and subsequent easing), not a strict periodic function.
  - |
    Normal-phase volume estimate is ~1150 logs/min (dominated by request flows), with low background router/automation logs.
  - |
    Scenario-sized volume estimate is ~52k–68k logs over ~40 minutes (request flows dominate; router/automation metrics add corroboration without overwhelming volume).
  - |
    Key diagnostic visibility is ensured by: router fwd_drop_metric and routing_recompute_metric (background), edge 504/503 response logs (per-request),
    DNS timeout logs (per-request), and automation pause/restart one-shots.
