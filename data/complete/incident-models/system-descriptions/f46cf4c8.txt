assumptions:
  - |
    To prevent contradictory location labeling in generated logs, the edge proxy is split into two components:
    edge_pop_affected emits only affected POP codes [ewr, ord, sjc, lon, ams] and edge_pop_unaffected emits only [syd].
    Atlanta (atl) is represented in router/traffic-manager telemetry rather than as an edge request origin in this slice.
  - |
    The backbone outage is modeled as an iBGP route export/policy mistake at the Atlanta router that makes many prefixes
    prefer Atlanta (higher local preference), causing traffic concentration and overload.
  - |
    To keep retry chronology correct, upstream retries are modeled as an internal upstream-fetch flow
    (http_req_affected_to_atl_fail_f) that emits per-attempt start/fail logs plus retry markers, while the
    client-facing completion log (edge_pop_affected.req_complete_err) is emitted once via a separate non-retrying flow
    (http_req_affected_client_err_f).
  - |
    The client-error flow path explicitly includes backbone/Atlanta hops even though only edge logs are emitted, so the
    coarse route context reflects the central misrouting mechanism.
  - |
    The later "core congestion" is modeled as the central observability pipeline emitting lag and explicit drop warnings;
    missing logs themselves are not modeled, only explicit drop indicators.
  - |
    ingest_eps in core_observability.ingest_metric is intended to reflect the ingestion rate for the modeled log stream
    (a representative slice), not backbone-wide telemetry volume.
  - |
    Normal-phase volume estimate: ~400 rpm * 3 logs/request ~= ~1200 logs/min from flows, plus ~5-20 logs/min background.
  - |
    Total scenario volume estimate: ~50k-70k logs total (flows dominate; background and one-shots are small),
    within the target 20k..100k envelope.
  - |
    Key diagnostic visibility: config commit (one-shot), elevated BGP export summaries and peer bestpath churn (background),
    frequent client 5xx/504 completions plus upstream retry markers (flows), mitigation marker (router disabled one-shot)
    plus post-mitigation neighbor/participation status (background), and later ingest drop warnings (background).
