  id: cloud_us_backbone_control_plane
  desc: >
    A multi-region cloud platform runs customer-facing regional APIs over a shared US backbone network.
    A regional network control plane programs routing and traffic engineering via BGP across multiple physical locations.
    Datacenter maintenance automation uses a cluster manager to deschedule/reschedule jobs during maintenance events.
    When the network control plane is absent long enough, parts of the backbone fail static briefly and then withdraw BGP,
    reducing capacity and causing packet loss that surfaces as elevated latency and intermittent API timeouts.

states: {n: normal, f: failure}

assumptions:
  - "The model focuses on one representative affected regional API (storage_api in us-east4) to capture the causal core: control plane descheduled → BGP withdrawal → backbone congestion/packet loss → timeouts."
  - "Multiple impacted regions and services from the post-mortem are represented implicitly via backbone_router region_pair metrics rather than modeling each service/region separately."
  - "Flow rpm values are global for the modeled region; per-host aggregates (storage_api.request_stats ok_rpm/err_rpm) reflect an approximate split across 3 API hosts."
  - "Control-plane absence is modeled primarily via cluster_manager evictions and monitoring alerts, not via direct net_control_plane logs (since the control plane cannot log while descheduled)."
  - "BGP neighbor IPs are modeled as realistic single IPs (not CIDR strings) to keep router logs plausible."
  - "Timeout request duration is modeled as seconds-scale (>=3s) to match retry/timeout behavior and the 504 dur_ms domain."
  - "Normal-phase volume estimate: ~600 logs/min (mostly storage request start/end), plus ~10 logs/min background."
  - "Expected total logs for the paired scenario (60 minutes) are ~40k (within the 20k–100k target), dominated by per-request API logs with moderate retries during failure."
