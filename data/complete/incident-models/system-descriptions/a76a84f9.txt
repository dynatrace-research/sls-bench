    uplink to an aggregation-switch pair using MLAG; disruptive MLAG failover can
    cause L2 churn and briefly block east/west traffic, impacting cluster heartbeats.

assumptions:
  - |
    Names and host counts are simplified; the model focuses on MLAG-induced L2 churn cascading into Pacemaker/DRBD fencing races.
  - |
    A reverse logical edge fileserver_cluster->web_app is included to make request paths that return results to the web tier traversable for log generation.
  - |
    Only one primary user flow family (git-over-HTTP) is modeled; other product features are omitted as they do not change the causal core here.
  - |
    To keep per-trace routing identity coherent in normal operation, web_app.storage_call.fs_host is constrained in state n to the active nodes
    that can emit fileserver_cluster.storage_op_ok (fs-a1/fs-b1). In failure it broadens to include either node of a pair.
  - |
    web_app.storage_call.timeout_ms is widened to cover multi-second upstream waits seen during the incident so that flow latency hints and timeout logs
    remain coherent without requiring extreme latency multipliers.
  - |
    agg_switch_pair.mlag_heartbeat_missed.peer_link is constrained to [up] so the log unambiguously represents the incident’s edge case:
    heartbeat missed while the peer link remains physically/electrically up.
  - |
    Normal traffic is modeled at ~300 rpm with 3 logs/request (~900 logs/min) to keep volume in-range without unrealistic per-request logging elsewhere.
  - |
    Key diagnostic anchors intended to be visible: agg_switch_pair.mlag_heartbeat_missed and agg_switch_pair.stp_topology_change spikes;
    fileserver_cluster.heartbeat_timeout and fileserver_cluster.stonith_ack_timeout increases; web_app access logs shifting from 200 to 5xx then to 503.
  - |
    Estimated total logs over a ~40 minute scenario are ~28k-35k (flows dominate; background switch/HA logs add ~1k-2k), within the 20k..100k target.
