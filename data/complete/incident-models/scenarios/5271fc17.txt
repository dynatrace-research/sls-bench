scenario:
  id: cf_like_bot_feature_file_over_limit_2025_11_18
  title: Oversized bot feature file triggers core proxy panics and widespread 5xx

  states: {n: normal, f: failure}

  summary: |
    The edge network normally serves HTTP traffic through an edge gateway and a core proxy that runs Bot Management.
    A ClickHouse permissions rollout changes metadata query results used by the bot feature-file builder, producing an oversized
    feature configuration artifact. Once propagated, the core proxy’s bot module exceeds its hard feature-count limit and panics,
    returning 5xx error pages to end users and breaking dependent services like KV and Access. Operators later mitigate by bypassing
    KV/Access and then pausing feature propagation, inserting a known-good file, and restarting proxies; most traffic recovers but a small residual error rate remains by scenario end.

  trigger_desc: |
    A subset of ClickHouse nodes begins returning duplicated metadata rows to the feature-file builder, which then produces an oversized
    bot feature file; this file is queued and distributed to the fleet, activating the proxy feature-count limit failure.

  time:
    total_minutes: 56
    phases:
      n: {start_min: 0, end_min: 28}
      f: {start_min: 28, end_min: 56}

  phases:
    n:
      desc: |
        End-user HTTP traffic is mostly successful with a small baseline of upstream-related 5xx. KV and Access operate normally.
        The bot feature file is generated periodically from ClickHouse metadata and distributed without issue; proxy bot processing
        remains within limits.
      flows: [http_user_success, http_user_baseline_5xx, kv_get_via_proxy_ok, access_auth_ok, bot_feature_publish_good, synth_probe_ok]

        increases response latency. As more ClickHouse shards are updated, oversized files become consistent and the system stops “recovering”
        between bad publishes. KV and Access experience widespread failures until mitigations reduce their dependency on the failing proxy path.
        Operators then pause automated feature generation/propagation, insert a known-good artifact, and restart core proxies; most traffic succeeds again, but some residual panics persist on unrestarted hosts.

          flows:
