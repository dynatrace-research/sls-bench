scenario:
  id: uscentral_gateway_corridor_packet_loss_may2022
  title: Packet loss and prolonged backbone reconvergence from central gateway campus

  states: {n: normal, f: failure}

  summary: |
    Customer API traffic from a central US edge traverses a backbone corridor to west-region services (Storage, SQL, Messages),
    while connectivity gateways run VPN and Interconnect health probes. A fiber-path component failure reduces bandwidth on the
    corridor and triggers automated reconvergence; because the intended second-best path is still being augmented, some traffic
    migrates to a third-best path and convergence takes longer than expected. Customers observe intermittent packet loss, elevated
    latency, and transient 5xx/errors, with some services (notably Storage and SQL) continuing to show impact after the corridor
    stabilizes due to backlog and delayed recovery.

  trigger_desc: |
    A component on a fiber path feeding the central US gateway campus fails, reducing available bandwidth on a backbone corridor
    and initiating automatic traffic migration to alternate paths.

  time:
    total_minutes: 45
    phases:
      n: {start_min: 0, end_min: 15}
      f: {start_min: 15, end_min: 45}

  phases:
    n:
      desc: |
        The corridor operates normally with low loss and stable RTT. Cloud Storage, Cloud SQL, and Messages API requests succeed
        with typical latency. VPN keepalives and Interconnect BFD probes succeed, and global routing propagation delay is low.
      flows: [gcs_api_call_n, cloudsql_op_n, messages_publish_n, vpn_keepalive_n, interconnect_bfd_n]
      manifestation:
        - netmon.corridor_health
        - cloud_router_cp.route_update_delay
        - api_edge_uscentral.edge_health

    f:
      desc: |
        After a corridor bandwidth reduction, the backbone begins reconverging. Packet loss alarms and interface drops appear,
        connectivity probes begin timing out, and routing propagation slows. Because a topology augmentation leaves the second-best
        path insufficient, some traffic is pushed to a third-best path, extending the migration. Downstream services show elevated
        latency and transient 5xx; later, SQL replication lag and messaging backlog warnings appear. As reconvergence completes,
        sustained packet-loss alarms and probe timeouts stop, but Storage and SQL continue to show residual elevated latency and
        occasional errors due to ongoing recovery.

      events:

          component: backbone_gateway_central
          event: |

            elevated drop counters.
          flows:

              count: 1

            - backbone_gateway_central.link_state_change

          why: |
            During topology augmentation, the intended second-best fallback lacks sufficient capacity, requiring some traffic to shift
            to a third-best path, which increases convergence time. This is partially observable via TE path selection markers and
            sustained loss alarms; the augmentation status itself is external context.
          flows:
            - messages_publish_err_f

            - interconnect_bfd_fail_f
          rate_multipliers:
            netmon.loss_alarm: 2.0
            vpn_keepalive_fail_f: 1.3

            messages_west.backlog_warn: 1.0

          latency_multipliers:
            messages_publish_ok_f: {p50: 1.2, p95: 1.4}

              count: 1
              hosts: [te-ctrl-1]

          event: |

          flows:

            netmon.loss_alarm: 0.0

          desc: |
