  id: api_degradation_two_db_bugs_plus_config_interaction
  title: Two outage windows from stalled-peer election bug then rollback+config CPU starvation

  states: {n: normal, f: failure}

  summary: |
    The payments API normally serves POST write requests by forwarding writes through a shard router to a database shard primary.
    The incident begins when the shard primary fails while two peers are stalled and missing replication-lag telemetry, triggering an election fault that leaves the shard without a primary and causes widespread API timeouts.
    After operators restart the shard nodes, the API recovers; later, a rollback of the election protocol combined with a shard configuration setting causes CPU starvation and a second outage window.
    Applying a configuration fix and restarting nodes restores the shard and the API, followed by a traffic ramp back to normal throughput.

  trigger_desc: |
    The shard primary crashes while two replicas are in a stalled state (including missing replication-lag metric reporting).
    Under these conditions, the newer election protocol (v2) hits a rarely-triggered failover fault and cannot elect a new primary, causing write timeouts that cascade into API errors.
