  id: billing_redis_readonly_auto_recharge_spike
  title: Redis master restart wipes balances and causes repeated auto-recharge charges

  states: {n: normal, f: failure}

  summary: |
    The system normally prices billable usage events, updates in-flight balances in Redis, and records a durable ledger in a relational DB.
    A network connectivity loss between Redis replicas and the Redis master triggers simultaneous full resynchronizations and overload.
    The on-call response restarts the Redis master with an incorrect configuration, wiping in-flight balance data and leaving Redis effectively read-only.
    With balances missing and writes failing, only auto-recharge-enabled accounts repeatedly charge cards until billing is taken offline; later re-enable still fails because Redis remains READONLY, causing a recurrence.

  trigger_desc: |
    Loss of network connectivity between Redis replicas and the Redis master causes all replicas to reconnect and request full synchronization at the same time.

      - min 39-45 (6m): offline usage (~250 rpm, 2 logs/req) => ~3.0k logs.
      - min 45-48 (3m): READONLY again; auto-recharge-enabled usage now uses balance_unwritable variant (~5 rpm, 5 logs/req) plus recharge execution => ~3.2k logs total including the main non-auto-recharge subset.
      - min 48-50 (2m): offline again (~250 rpm, 2 logs/req) => ~1.0k logs; refund_progress starts (2/min global) => ~4 logs.

    - Total log estimate is ~50k-75k including background metrics (pricing_lag_metric, redis stats/replication logs, monitor ticks), within the 20k-100k target; key failure signals (role_changed/role_status, READONLY errors, recharge_requested_* + gateway charges, offline deferrals) are likely to appear in a single run.
