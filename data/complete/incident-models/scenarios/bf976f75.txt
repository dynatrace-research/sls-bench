  id: incident_2025_03_12_extstore_overload_memcached_envvars
  title: Mis-deploy breaks Memcached envvars, overloads External Storage and degrades log-derived observability

  states: {n: normal, f: failure}

  summary: |
    Non-user-facing MediaWiki deployments (api-int, parsoid, jobrunner) normally hit Memcached and only occasionally stress
    the External Storage DB cluster. A Scap deployment rolls out a mismatched PHP image/envvars mount so the services
    default to Memcached on localhost, causing cache failures and DB fallback reads/writes. External Storage connections
    and query timeouts rise, causing high latency and database-related errors, while the flood of memcached error logs
    overwhelms Logstash and leads to missing/blank log-derived dashboards and delayed/missing alerts. User-facing traffic
    is minimally affected because the impacted deployments are auxiliary.

  trigger_desc: |
    Scap deployment for the PHP 8.1 rollout is executed with -Dbuild_mw_container_image:False, which (unexpectedly)
    skips updating helmfile-defaults. Pods run the older PHP image while envvars.inc is mounted in the new PHP include
    path, so php-fpm does not load MCROUTER_SERVER and MediaWiki uses the default 127.0.0.1:11213.

      flows:
        - api_int_request_ok

        Mitigations reduce background job pressure but do not restore Memcached configuration by the end of the scenario.
