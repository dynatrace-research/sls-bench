scenario:
  id: us_backbone_control_plane_deschedule_20190602
  title: Network control plane descheduled leads to BGP withdrawals and backbone packet loss

  states: {n: normal, f: failure}

  summary: |
    A multi-region cloud backbone normally carries traffic for regional customer APIs with low latency and minimal errors.
    A rare maintenance event triggers automation that deschedules network control plane jobs across multiple locations.
    After a short fail-static window, BGP sessions drop and routes are withdrawn, sharply reducing backbone capacity and causing packet loss.
    Customers experience elevated latency and intermittent 504 timeouts from a representative regional Storage API, while monitoring/tooling also degrades.

  trigger_desc: |
    Maintenance automation starts a rare maintenance event and (due to misconfiguration plus a bug) issues a deschedule request that evicts
    multiple independent network control plane clusters across physical locations.

  time:
    total_minutes: 60
    phases:
      n: {start_min: 0, end_min: 25}
      f: {start_min: 25, end_min: 60}

  phases:
    n:
      desc: |
        The regional Storage API in us-east4 serves steady customer traffic with low tail latency and near-zero errors.
        The network control plane emits heartbeats, and backbone utilization remains moderate. Monitoring scrapes succeed.
      flows: [storage_object_get_n]
      manifestation:
        - storage_api.req_end_200
        - storage_api.request_stats
        - net_control_plane.heartbeat
        - monitoring.scrape_ok
        - backbone_router.link_utilization

    f:
      desc: |

        Customer-facing Storage API calls show increased latency and a rising fraction of 504 timeouts with retries.
        Tooling and monitoring contend with the same congested network and begin timing out, slowing mitigation and restoration.

      events:

            allows multi-cluster, multi-location descheduling. Directly observable via automation start marker and eviction logs; control plane absence

            BGP sessions drop and routes are withdrawn on congested backbone links, sharply increasing packet loss.
            Storage API latency spikes and 504 timeouts become common.
          why: |
            The cluster manager completes most evictions soon after the maintenance request is issued; after that only residual/late evictions occur.
            With the network control plane absent long enough, some routing between impacted locations is withdrawn, reducing capacity and causing congestion.
            Directly observable via BGP session-down markers and packet-loss metrics; customer impact is observed as 504s and higher p95 latency.
          flows: [storage_object_get_ok_f, storage_object_get_timeout_f]
          rate_multipliers:

            storage_object_get_timeout_f: 12.0

            Loss of the control plane does not immediately break forwarding (fail static), but after a short window routing withdraws,

    - "Per-host stats (storage_api.request_stats ok_rpm/err_rpm) are modeled as approximate splits of the global flow RPMs across 3 storage_api hosts, and allow peaks that correspond to the event multipliers applied to timeout flows."
