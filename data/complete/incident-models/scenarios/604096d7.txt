  id: rds_clogs_cache_refresh_crash_loops
  title: RDS CPU stall triggers cache-refresh thundering herd and API OOM crash loops

  states: {n: normal, f: failure}

  summary: |
    The system serves a high-volume /v1/bounce endpoint, usually satisfied from an in-process TTL cache with occasional
    DB refreshes against MySQL RDS. A write-heavy disk-usage cron workload and already-high baseline DB utilization
    increase query latency enough that many handlers concurrently refresh expired cache keys, driving a thundering herd
    of DB queries. Elevated timeouts and gateway retries amplify load; API servers accumulate goroutines/memory and
    enter OOM crash loops that clear caches and further shift reads to RDS, producing a sustained partial API outage.

  trigger_desc: |
    A disk-usage stats run begins writing heavily to RDS while the database is already running at elevated baseline CPU.
    The added write load raises read latencies, increasing cache expirations and concurrent refreshes.

  time:
    total_minutes: 44
    phases:
      n: {start_min: 0, end_min: 22}
      f: {start_min: 22, end_min: 44}

  phases:
    n:
      desc: |

        background rate and do not noticeably affect DB performance.
      flows:
        - api_get_bounce_cache_hit
        - api_get_bounce_cache_miss
        - disk_usage_write_stmt
      manifestation:
        - rds_mysql.rds_metrics

        - api_gateway.gw_out

        multiply. Gateway retries increase total upstream work, while cache refresh concurrency drives large numbers of
        in-flight goroutines for the same keys. As memory rises, API servers OOM and restart, clearing their caches and
        pushing even more refresh traffic to RDS. A manual scale-down reduces some load but does not fully resolve the
        stalled DB + crash-loop condition before the scenario ends.

      events:

          component: disk_usage_worker

            Disk-usage writes spike, increasing write contention on RDS and raising read latencies for cache refreshes.
          why: |

            writes reduce DB headroom and increase query latency. Directly observable via increased disk-usage write
            traffic and elevated RDS metrics.
