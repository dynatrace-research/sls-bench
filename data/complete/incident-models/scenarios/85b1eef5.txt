scenario:
  id: inc_2023_01_24_service_tokens_overwrite_staggered_sync
  title: Service token secrets overwritten by last-seen updater; staggered global sync causes auth failures

  states: {n: normal, f: failure}

  summary: |
    Cloudflare-internal services authenticate to protected endpoints using service tokens enforced at an edge gateway.
    A release to add “last seen at” token metadata accidentally wrote back tokens with an empty client_secret due to
    redacted reads, silently corrupting a few internal accounts’ tokens. The impact was delayed and staggered because
    invalid token material only became effective after it synced to the edge configuration, causing bursts of 403
    denials and downstream product errors (notably Zero Trust posture flows and later control-plane API calls).

  trigger_desc: |
    Access engineering deploys a “service_token_last_seen” feature that updates token metadata based on login events.
    The updater reads tokens with secrets redacted and then writes updates, persisting an empty-string client_secret.

  time:
    total_minutes: 56
    phases:
      n: {start_min: 0, end_min: 28}
      f: {start_min: 28, end_min: 56}

  phases:
    n:
      desc: |
        Device posture uploads and reads succeed through the edge gateway, and control-plane internal API calls
        succeed. Token updates are rare and limited to normal administrative maintenance.
      flows: [posture_upload_ok, posture_read_ok, internal_api_call_ok]
      manifestation:
        - edge_auth_gateway.edge_access_ok_posture
        - device_state_service.posture_ingest_ok
        - gateway_policy_engine.posture_fetch_ok
        - api_orchestrator_service.api_call_ok
        - edge_auth_gateway.auth_denied_metric
        - edge_auth_gateway.http_5xx_metric

    f:

        of internal accounts. A rollback stops further overwrites, but already-corrupted tokens remain in storage.
        As Config Sync applies those corrupted tokens to the global edge configuration, the edge gateway begins to
        reject requests using those tokens with 403, first impacting Zero Trust posture paths and later control-plane
        internal API calls. Mitigation restores the WARP/Zero Trust account token, while the API account remains
        degraded at the end of this modeled window.

          why: |
            Token reads used for last-seen updates redact client_secret; the write transaction uses that redacted view.
            This corruption is directly observable as token-write logs with client_secret_len=0; user impact is not yet
            visible because invalid token material has not been applied to the edge configuration.
          flows: [posture_upload_ok_f, posture_read_ok_f, internal_api_call_ok_f]
          rate_multipliers:

          component: access_token_service

            The release is rolled back, stopping further last-seen polling and token overwrites.
          why: |
            Disabling the updater halts additional corrupt writes, but previously overwritten tokens remain and may be

          flows: [posture_upload_ok_f, posture_read_ok_f, internal_api_call_ok_f]
