scenario:
  id: knight_powerpeg_rlp_incident
  title: RLP flag activates legacy Power Peg on one SMARS host, then rollback spreads it

  states: {n: normal, f: failure}

  summary: |
    The system normally routes broker parent orders through SMARS and executes them on NYSE with bounded child order activity.
    Shortly before heavy order flow, an internal alerting channel emits many low-priority emails referencing "Power Peg disabled",
    reflecting a latent deployment/version inconsistency. When the RLP flag is enabled, one legacy SMARS host interprets the flag
    as Power Peg activation and begins generating unthrottled child orders, causing extreme executions and exposure in account 33.
    An attempted rollback spreads the legacy behavior to all hosts; SMARS is eventually shut down, leaving order flow rejected and large positions outstanding.

  trigger_desc: |
    The RLP feature flag is enabled for production order flow while one SMARS host is still running a legacy build where the repurposed flag maps to Power Peg logic.

  time:
    total_minutes: 46
    phases:
      n: {start_min: 0, end_min: 23}
      f: {start_min: 23, end_min: 46}

      desc: |
        SMARS routes parent orders normally using the updated build (rlp_v2) with the RLP flag off.
        NYSE execution summaries show small, bounded execution counts, and PMON snapshots show low exposure.
      flows: [parent_order_normal]
      manifestation:
        - smars_router.heartbeat
        - smars_router.child_order_stats
        - pmon.position_snapshot
        - order_gateway.respond_ok

    f:
      desc: |
        The failure phase begins as the system enables the RLP flag for live flow while a latent deployment discrepancy exists.
        Initially only a fraction of orders hit a legacy host and trigger Power Peg; NYSE and PMON then detect anomalies.
        A misguided rollback expands the legacy behavior to all hosts, amplifying child order generation and executions.
        SMARS is finally shut down, halting routing but leaving the firm with large unintended positions and rejecting new orders.

      events:

              count: 1

          manifestation:
            - nyse_venue.volume_alert

          why: |
            Manual incident response assumes the older build is safer; because the flag maps to Power Peg in the legacy build, rollout expands the faulty behavior (partially observable via build values and spike in SMARS stats).

            - pmon.position_snapshot

            The attempted rollback increases the blast radius by making all hosts interpret the live RLP flag as the legacy Power Peg activation path, turning a 1/8 host issue into a fleet-wide runaway.

    - |
