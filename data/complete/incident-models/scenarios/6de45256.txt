scenario:
  id: lb_stale_config_rollback_gfe_gc_20170405
  title: Stale LB config rollback triggers GFE GC/restarts and later config-update freeze

  states: {n: normal, f: failure}

  summary: |
    The system normally serves HTTPS traffic from a fleet of GFE proxies and applies configuration updates via a master-controlled push process.
    A mastership transition to a replica that could not read recent configuration snapshots caused the control plane to revert to an out-of-date "known good" config.
    Recently modified load balancers lost required config entries (100% 502s for that subset) and later the large deletion set triggered heavy GC on GFEs, leading to health check failures and frequent restarts (overall ~25% 502s).
    Operators switched to a healthy master and forced a fresh config reload to mitigate 502s, then paused further configuration updates, causing some deployments to fail.

  trigger_desc: |
    A configuration-master replica loses access to the distributed file system, then becomes leader and initiates a config push; its canary validation fails and it reverts all GFEs to the newest configuration snapshot it can read (stale).

  time:
    total_minutes: 40
    phases:
      n: {start_min: 0, end_min: 18}
      f: {start_min: 18, end_min: 40}

  phases:
    n:
      desc: |
        GFEs serve stable load balancers successfully with low background GC and occasional storage RPC warnings.
        Deployments submit config changes which are accepted and pushed via routine push cycles (canary passes, then global apply).
      flows: [client_https_request_ok_n, lb_config_push_cycle_n, app_flex_deploy_success_n]
      manifestation: [gfe.access_200, config_master.heartbeat, gfe.cpu_sample]

    f:
      desc: |
        A newly elected config master leader cannot read recent snapshots and treats a canary failure as a signal to revert to "known good",
        but because it only sees older snapshots the rollback is substantially out of date.
        Recently modified load balancers immediately begin failing due to missing config entries, and shortly after, GFEs experience GC pressure
        from deleting many configurations; health checks fail, frequent restarts occur, and stable load balancers experience intermittent 502s.
        Near the end, operators switch to a healthy master and force a one-time reload of a fresh configuration to mitigate errors; regular configuration updates are then paused.
